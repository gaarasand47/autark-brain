# Generation Naming and Value Rule

A generation number is permitted only for a major, end-to-end organism capability that changes what Autark can do in the world. Schemas, refactors, tests, persistence hardening, documentation, one adapter, minor authority refinement and bug fixes are stages/releases/hardening, never new generations.

Before numbering, answer: what is fundamentally new; does it operate end-to-end; is evidence real; does it create utility/resilience/intelligence/economic value; is it broad enough; and is the predecessor sufficiently complete? If weak, continue the current generation. Architecture is not implementation, tests are not completion, simulations are not real operation, and routine manual intervention or hidden inherited blockers invalidate completion. Safety must constrain authority without eliminating useful work.

Gen-3F is hardening; Gen-4A is allowed only for a coherent capability within Gen-4. Gen-5 cannot be declared until real enterprise capability and value evidence exist.
